## Performance

| Tag | Change |
|---:|---|
| ![improvement] | <details><summary>The periodic autosave now only rewrites data that actually changed</summary><br>Previously every autosave rewrote all bank, item, company and metadata files on disk each interval whenever any player was online, even when nothing had changed. Each save area now tracks whether it was modified and the timer skips the ones that were not, cutting needless disk writes on busy and idle servers alike. A full save is still forced on world save and on shutdown, so nothing is ever lost.</details> |

## API

| Tag | Change |
|---:|---|
| ![breaking] | <details><summary>Any item can now be blacklisted — including the base money currency — and the old "not-removable" concept was removed</summary><br>Previously `banksystem:money` was permanently protected and could never be disallowed. That protection, along with its API (`getNotRemovableItems` / `isItemIDNotRemovable` and their async variants), has been removed. Money is now simply a default-on item: it is created on new accounts unless an admin disallows it, and an empty money slot is pruned like any other. Mods embedding BankSystem should drop any calls to the removed methods.</details> |
| ![improvement] | <details><summary>Bank-slot lookups can now return "no slot" when a currency has been disallowed</summary><br>`getOrCreatePersonalBank` and the account-level bank creation now return null for an item an admin has blacklisted, instead of resurrecting a slot for it. All built-in callers (dividends, scheduled payouts, terminals, ATM, upload block) already treat a missing slot gracefully; downstream mods should null-check the result.</details> |

## CLI

| Tag | Change |
|---:|---|
| ![removal] | Removed the non-functional `/bank enableNotifications` and `/bank disableNotifications` commands — the notification system they referenced was never implemented. |
| ![feature] | <details><summary>`/banksystem disallowItem` now works on every item, including money, and reports exactly who was affected</summary><br>Disallowing an item that players are holding now clears it from every account, prints a full per-account dump (owner, free and locked balance) to the server console, and shows the admin a chat summary capped at 20 accounts with an "…and N more" line for the rest. There is no refund. Re-allowing a previously disallowed item (`/banksystem allowItem`) restores it to the auto-create schedule for future accounts.</details> |
| ![feature] | <details><summary>Disallowing an item now cleans up companies that used it as their payout currency</summary><br>When an item is disallowed, every company that pays dividends or scheduled payouts in that item has its currency reset to money (or, if money itself is the disallowed item, to an "unset" state that must be reconfigured before it can pay again). Any payout schedule paying the disallowed item is paused rather than deleted, and a company's own hand-paused schedules are left exactly as the owner set them. Re-allowing the item automatically resumes only the schedules that were paused by the ban. The admin sees a chat summary of the affected companies and how many schedules were paused, with the full list written to the server console.</details> |
| ![bugfix] | Founding a company through `/company create` now gives its bank account the same default money and currency slots a manually-created account gets, instead of leaving it empty. |
| ![bugfix] | The `/banksystem disallowItem` currency-ban chat summary no longer ends with an empty, dangling list — companies whose payout schedule was paused are now always included, even when the company's own currency setting wasn't reset. |

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Server admins can now cap how many bank accounts and companies each player may create</summary><br>Two new settings appear under the Player group of the in-game Mod Settings screen: "Max bank accounts per player" and "Max companies per player" (both default 3). Only accounts a player creates themselves count — the personal account, being invited to someone else's shared account, and being a company employee never count against the limit. Because founding a company also creates a bank account, a company can be founded only while the player still has a free account slot. Set a value to -1 for unlimited or 0 to disallow. The limits are read live at creation time, apply on both single- and multi-server setups, and a clear chat message explains any rejection.</details> |
| ![bugfix] | The "Max bank accounts per player" and "Max companies per player" settings now accept a leading minus sign, so the documented `-1` (unlimited) value can actually be typed into the Mod Settings screen. |
| ![bugfix] | A bank account still owned by a company can no longer be deleted out from under it — the server refuses the request, and the Bank Account Management screen now greys out the Delete Account button for such accounts instead of letting the click fail silently. |
| ![bugfix] | Resuming a paused payout schedule — manually from the Payouts screen, or automatically when a banned currency is re-allowed — now restarts its countdown from that moment, instead of resuming with a stale, longer-than-expected time remaining. |

## Documentation

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>Settings reference corrected — the autosave key had been renamed and the history-retention settings were missing</summary><br>The configuration guide still described `SAVE_INTERVAL_MINUTES`, which was replaced by the seconds-based `SAVE_INTERVAL_SECONDS` in 2.1.0, and still presented `BALANCE_SNAPSHOT_MAX_RECORDS_PER_ITEM` as enforced although the tiered retention plan superseded it. Both entries now describe what the server actually does, and the previously undocumented `BALANCE_SNAPSHOT_HEARTBEAT_MINUTES`, `BALANCE_HISTORY_RETENTION_SWEEP_MINUTES` (including its age bands) and `CONFIRM_ITEMID_REPAIR` settings were added.</details> |
| ![improvement] | Block guide extended with the features it never covered — the Bank Terminal's balance-history chart (timescale buttons, background history streaming, item search and series filters), the ATM's Withdraw and Convert tabs, multi-block display auto-linking, and JEI recipe lookup from the bank item list. |
| ![improvement] | Command reference completed with the `/company` family, `/banksystem backup` and `/banksystem symbols`, plus a table pointing at the screens that own the actions with no chat equivalent. |
| ![improvement] | Administration guide gained a backup section explaining how to take a consistent database copy while the server runs, and a short description of the transaction ledger. |
| ![improvement] | Developer documentation brought up to date — the API reference lists every entry point (payouts, dividends, share visuals, currency providers, price provider) and the full event catalog, the events guide documents the payout and dividend events, the async-forwarding guide counts the company request surface, and the documentation index now links the Currency Integration and Item Price Provider guides. |

## Internal

| Tag | Change |
|---:|---|
| ![improvement] | Share-symbol textures now live under the world's canonical `data/BankSystem` folder alongside the rest of the mod's data; existing stores are migrated automatically on first load. |
| ![improvement] | Each persisted save unit (bank data, item registry, companies, bindings, metadata) now carries a dedicated dirty flag set on mutation and cleared after a successful write, so the autosave timer can skip unchanged units while forced saves (world save, shutdown) always write every unit. |
| ![improvement] | Admin-disallowed items are now tracked in a runtime blacklist that persists with the bank data, wins over the "allow all items" setting, and is cleared again when the item is re-allowed. Account seeding runs every default slot (money and each detected external currency) through one allow/blacklist gate, so a disallowed currency never leaves a phantom empty slot. |
| ![hardening] | Payout schedules now carry a persisted marker distinguishing a pause caused by a currency ban from an owner's manual pause, and every place that reads a company's configured currency treats the new "unset" state as "no currency configured" — refusing to pay with a clear reason instead of crashing or minting into a void. |
| ![removal] | Removed the unused `ITEM_TRANSFER_TICK_INTERVAL` server setting, which was present in the config but read by no active code path. |
| ![improvement] | Removed the leftover `enableBankNotifications` flag from the user data model and the unused permission flag from `BankUserData` — both were dead weight left over from the removed bank-notification commands. |
