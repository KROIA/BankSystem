# 2.0.5 — In Development

## API

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>External currency mod support foundation — SPI for binding third-party currency accounts to BankSystem accounts</summary><br>New `ExternalCurrencyProvider` SPI in `api.currency` lets third-party mods (Numismatics, Lightman's Currency, ...) expose their accounts for optional binding. Per-account, per-item-slot bindings route balance operations through the external provider while preserving BankSystem's locked-balance protocol. Includes `ExternalAccount` (deposit/withdraw/membership-sync), `ExternalAccountRef` (binding identity record), and `ProviderFeature` (capability flags). Binding management via five ARRS requests: list providers, list bindable accounts per player, bind, unbind, list bindings for an account. Registered providers discovered via Architectury service loader; adapters are optional runtime dependencies. Locked balance tracked locally in per-world `BankAccountBindings` savedata — external mods don't have a locked concept. Drift-clamp protocol per existing `ISyncServerBank` contract handles external balance drop below locked amount. Shared-account permission mapping: BankSystem WITHDRAW users synced to external membership via `syncMembership()`. Cascade unbind on account/bank deletion.</details> |
| ![feature] | <details><summary>Five ARRS requests for external currency binding operations</summary><br>`ListCurrencyProvidersRequest` (enumerate registered providers), `ListBindableAccountsRequest` (query per-player bindable accounts from a provider), `BindAccountToBankRequest` (create binding), `UnbindAccountFromBankRequest` (drop binding + copy external balance back to native storage), `ListBindingsForAccountRequest` (enumerate bindings for a BankSystem account). All guarded by admin permission + master-only execution. Responses carry `ExternalAccountRef` records or binding snapshots. Enable runtime configuration of which external accounts back which BankSystem account slots.</details> |

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | `BankAccountBindingsScreen` — manage which external currency accounts are bound to each item slot in a BankSystem account. Reachable from account management screen's new "Manage Bindings" button. Shows current binding state per slot, lets players pick from available accounts via provider dropdown + account list. Unbind restores native BankSystem storage with external balance copied in. Per-slot status indicators: bound (shows provider + account label), unbound (native storage), error states for unreachable/invalid providers. |

## Integrations

| Tag | Change |

Deposits, withdrawals, locked-balance operations, and StockMarket trading route through bound Numismatics accounts transparently. ## Internal

| Tag | Change |
|---:|---|
| ![feature] | `BankAccountBindings` per-world savedata — tracks `(bankAccountId, itemId) → (providerId, externalAccountKey, currencyKey, lockedBalance, boundAt)` rows. Loaded/saved via `IBankSystemDataHandler` as separate top-level file. Clean unbind deletes row (no account NBT mutation). `lockedBalance` field preserves locked-amount semantics without touching external mod state. |
| ![feature] | `ServerBank` refactor — balance operations delegate to bound external account when binding row exists for `(accountId, itemId)`. Reads (`getBalance/getLockedBalance/getTotalBalance`) route per locked-balance protocol: `getBalance() → external.getBalance() - lockedLocal`, `getLockedBalance() → lockedLocal`, `getTotalBalance() → external.getBalance()`. Writes (`deposit/withdraw/lock/unlock/setBalance`) route accordingly. Locked amount stays 100% local — `lockAmount/unlockAmount` don't touch external; `withdrawLocked` withdraws from external then decrements local. Existing `setBalance` clamp contract handles drift (external drops below locked → clamp + WARN). Native storage bypassed when binding exists but preserved for unbind restoration. |
| ![feature] | `ServerBankAccount.removeBankRequest` cascade-unbinds all slots on account deletion. `ServerBankManager.removeBankForItem` cascade-unbinds all affected bindings on item removal. Unbind copies external balance back to native storage before dropping binding row so restoring an account doesn't orphan funds. |
| ![feature] | `StubCurrencyProvider` testing infrastructure — in-memory fake external mod with personal + shared account support, configurable balance caps, membership tracking, simulated deposit/withdraw. Used by `ExternalCurrencyBindingTests` (7 in-game test cases: round-trip bind/deposit/read, locked-balance protocol, drift-clamp, overflow guard, shared-account membership sync, unbind flow, shared-mismatch rejection). |
| ![feature] | Numismatics adapter uses reflection-based access to `dev.ithundxr.createnumismatics.content.bank` classes — no hard compile-time dependency keeps BankSystem loadable when Numismatics is absent. `NumismaticsProvider` registered via `Platform.isModLoaded("numismatics")` gate. Falls back gracefully with dedup'd WARN when reflective API names mismatch. |
| ![feature] | `NumismaticsAdapterTests` — 3 in-game smoke tests (round-trip balance, shared account membership sync, overflow guard). Skipped automatically when Numismatics mod not loaded. |
| ![improvement] | Localization: 25 new lang keys across `en_us`, `de_de`, `de_ch`, `zh_cn` for binding UI — provider dropdown, account selection, bind/unbind buttons, status messages, error states, binding management screen title/labels. |
