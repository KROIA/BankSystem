# 2.0.5 — In Development

## API

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>External currency mod support foundation — SPI for binding third-party currency accounts to BankSystem accounts</summary><br>New `ExternalCurrencyProvider` SPI in `api.currency` lets third-party mods (Numismatics, Lightman's Currency, ...) expose their accounts for optional binding. Per-account, per-item-slot bindings route balance operations through the external provider while preserving BankSystem's locked-balance protocol. Includes `ExternalAccount` (deposit/withdraw/membership-sync), `ExternalAccountRef` (binding identity record), and `ProviderFeature` (capability flags). Binding management via five ARRS requests: list providers, list bindable accounts per player, bind, unbind, list bindings for an account. Registered providers discovered via Architectury service loader; adapters are optional runtime dependencies. Locked balance tracked locally in per-world `BankAccountBindings` savedata — external mods don't have a locked concept. Drift-clamp protocol per existing `ISyncServerBank` contract handles external balance drop below locked amount. Shared-account permission mapping: BankSystem WITHDRAW users synced to external membership via `syncMembership()`. Cascade unbind on account/bank deletion.</details> |
| ![feature] | <details><summary>Five ARRS requests for external currency binding operations</summary><br>`ListCurrencyProvidersRequest` (enumerate registered providers), `ListBindableAccountsRequest` (query per-player bindable accounts from a provider), `BindAccountToBankRequest` (create binding), `UnbindAccountFromBankRequest` (drop binding + copy external balance back to native storage), `ListBindingsForAccountRequest` (enumerate bindings for a BankSystem account). All guarded by admin permission + master-only execution. Responses carry `ExternalAccountRef` records or binding snapshots. Enable runtime configuration of which external accounts back which BankSystem account slots.</details> |
| ![feature] | <details><summary>`BankSystemAPI.unregisterCurrencyProvider(providerId)` — drop a registered currency provider</summary><br>Symmetric teardown counterpart to `registerCurrencyProvider`. Real currency-mod adapters normally live for the JVM lifetime, but the in-game test suite's stub provider needs to drop itself when the tests finish — otherwise the stub and any accounts the last test left behind leak into the production binding UI. Returns `true` when a provider was removed, `false` for unknown/null ids. Idempotent.</details> |
| ![feature] | `ExternalCurrencyProvider.getBaseCurrencyItemId()` — providers may declare the single item they are authoritative for (e.g. `"numismatics:spur"`). BankSystem uses this to reject nonsense bindings (e.g. a diamond slot bound to Numismatics) and to auto-seed the matching slot on account creation. Default returns `null` (item validation opt-out). |
| ![feature] | `ExternalAccount.nativeScale()` — providers may declare their indivisible-unit granularity in raw BankSystem units. Used by the bound-slot code path to split every balance op into a whole-native-unit external delta plus a sub-unit dust remainder persisted in the binding row. Keeps money conservation exact so sub-native fractions never silently vanish. Default returns `1` (no fractional handling required). |
| ![improvement] | `ListCurrencyProvidersRequest.ProviderInfo` now carries the provider's declared base currency item id, so the client can pre-validate slot/provider item matches before opening the account picker. |

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | `BankAccountBindingsScreen` — manage which external currency accounts are bound to each item slot in a BankSystem account. Reachable from account management screen's new "Manage Bindings" button. Shows current binding state per slot, lets players pick from available accounts via provider dropdown + account list. Unbind restores native BankSystem storage with external balance copied in. Per-slot status indicators: bound (shows provider + account label), unbound (native storage), error states for unreachable/invalid providers. |
| ![feature] | `InfoPopupScreen` — single-button acknowledgment popup for informational messages (errors, warnings, status reports). Sibling to `AskPopupScreen` for cases where the user is being told a result rather than asked a Yes/No question. |
| ![feature] | <details><summary>Bank terminal remembers the last-selected account across every terminal</summary><br>The player's last-selected account is now persisted in their global player data instead of per block. Opening any bank terminal restores the account you last used, on any terminal, on any server. Falls back to the terminal's per-block binding, then to the personal account, when no last-selected account is stored yet.</details> |
| ![improvement] | <details><summary>Binding is now allowed even when the slot already holds funds — no more "withdraw everything first" hurdle</summary><br>Local free balance is auto-transferred to the external account on bind (whole-native portion deposited, sub-native remainder preserved as dust in the binding row so no fraction is lost). Locked balance is carried over into the binding row so pending market orders keep referring to the same amount through the bound slot. Removes the "balance is not zero, withdraw first" popup entirely.</details> |
| ![improvement] | <details><summary>Unbind flow now offers a choice — keep funds on BankSystem or on the external provider</summary><br>Replaces the previous Yes/No confirmation dialog with a three-button choice (Keep on BankSystem / Keep on &lt;provider&gt; / Cancel). "Keep on BankSystem" recovers everything locally with no dust loss; "Keep on &lt;provider&gt;" leaves the external balance untouched, returns locked funds locally, and discards the sub-native dust with a clear warning label.</details> |
| ![improvement] | `BankAccountManagementScreen` layout: the header buttons no longer overlap — left column narrowed to 2:3 ratio so Bindings / Save Changes / Delete Account / Close have breathing room even on short account names. |
| ![improvement] | Bindings screen shows a clear item-mismatch message when the slot's item doesn't match the provider's declared base currency (e.g. trying to bind a `minecraft:emerald` slot to Numismatics/spur). Client-side pre-check avoids walking through the picker only to fail on the server. |
| ![bugfix] | Fresh personal accounts (from player join or `/bank create <name>`) now auto-seed the money slot **plus** a slot for every registered currency provider's base currency (e.g. `numismatics:spur`). Previously the spur slot had to be created manually before binding a Numismatics account. |

## Internal

| Tag | Change |
|---:|---|
| ![feature] | `BankAccountBindings` per-world savedata — tracks `(bankAccountId, itemId) → (providerId, externalAccountKey, currencyKey, lockedBalance, boundAt)` rows. Loaded/saved via `IBankSystemDataHandler` as separate top-level file. Clean unbind deletes row (no account NBT mutation). `lockedBalance` field preserves locked-amount semantics without touching external mod state. |
| ![feature] | `ServerBank` refactor — balance operations delegate to bound external account when binding row exists for `(accountId, itemId)`. Reads (`getBalance/getLockedBalance/getTotalBalance`) route per locked-balance protocol: `getBalance() → external.getBalance() - lockedLocal`, `getLockedBalance() → lockedLocal`, `getTotalBalance() → external.getBalance()`. Writes (`deposit/withdraw/lock/unlock/setBalance`) route accordingly. Locked amount stays 100% local — `lockAmount/unlockAmount` don't touch external; `withdrawLocked` withdraws from external then decrements local. Existing `setBalance` clamp contract handles drift (external drops below locked → clamp + WARN). Native storage bypassed when binding exists but preserved for unbind restoration. |
| ![feature] | `ServerBankAccount.removeBankRequest` cascade-unbinds all slots on account deletion. `ServerBankManager.removeBankForItem` cascade-unbinds all affected bindings on item removal. Unbind copies external balance back to native storage before dropping binding row so restoring an account doesn't orphan funds. |
| ![feature] | `StubCurrencyProvider` testing infrastructure — in-memory fake external mod with personal + shared account support, configurable balance caps, membership tracking, simulated deposit/withdraw. Used by `ExternalCurrencyBindingTests` (7 in-game test cases: round-trip bind/deposit/read, locked-balance protocol, drift-clamp, overflow guard, shared-account membership sync, unbind flow, shared-mismatch rejection). |
| ![feature] | Numismatics adapter uses reflection-based access to `dev.ithundxr.createnumismatics.content.bank` classes — no hard compile-time dependency keeps BankSystem loadable when Numismatics is absent. `NumismaticsProvider` registered via `Platform.isModLoaded("numismatics")` gate. Falls back gracefully with dedup'd WARN when reflective API names mismatch. |
| ![feature] | `NumismaticsAdapterTests` — 3 in-game smoke tests (round-trip balance, shared account membership sync, overflow guard). Skipped automatically when Numismatics mod not loaded. |
| ![improvement] | Localization: 25 new lang keys across `en_us`, `de_de`, `de_ch`, `zh_cn` for binding UI — provider dropdown, account selection, bind/unbind buttons, status messages, error states, binding management screen title/labels. |
| ![bugfix] | <details><summary>Server-side bind semantics rewritten so binding never loses funds or orphans locked balances</summary><br>Bind now auto-transfers the local free balance to external (whole-native portion → external deposit; sub-native remainder → row `dustBalance`) instead of refusing outright when the slot has funds. Locked balance is carried into the binding row's `lockedBalance` field so pending orders remain valid through the bound slot. `writeLocalFieldsForUnbind_internal(0, 0)` zeroes local free+locked in one atomic step to avoid ever exposing an intermediate state where the bound slot has both a local and external balance.</details> |
| ![bugfix] | <details><summary>Unbind flow rewritten around the three-button user choice</summary><br>Case A (keep on BankSystem): withdraw all external funds locally, materialize `ext + dust` as local free plus `locked` as local locked — no fractional loss. Case B (keep on provider): external is left untouched, `locked` returns as local locked (belongs to pending orders that referenced the slot), sub-native dust is discarded with a clear warning label in the UI. Case C (provider unavailable): local zeroed, row removed — external funds recoverable once the mod is reinstalled and re-bound. |
| ![bugfix] | <details><summary>Locked-balance protocol switched to transactional-lock semantics</summary><br>`lockAmount` now physically withdraws from external (whole-native portion) and mirrors the reserved amount into the binding row's `lockedBalance`. `withdrawLocked` decrements the row locked field only — external was already reduced at lock time. `unlockAmount` deposits the released amount back to external and zeroes the row locked field. Removes the earlier "external drift below locked → drift-clamp" scenario entirely, since external is now always at-most `>=` reserved.</details> |
| ![hardening] | <details><summary>`StubCurrencyProvider` no longer leaks into the production binding UI</summary><br>New `StubCurrencyProvider.teardown()` clears state and calls `unregisterCurrencyProvider`. `ExternalCurrencyBindingTests.teardown()` calls the new method instead of `reset()`. Previously, running `/banksystem test` once left the stub (and any accounts the last test created) visible in the binding UI for the rest of the JVM session.</details> |
| ![hardening] | <details><summary>`ExternalCurrencyBindingTests` — five new hardening cases and a fix for test ordering</summary><br>Adds `default_slot_seeding_money_plus_provider_currency`, `bind_preserves_locked_balance_into_binding_row`, `bind_overflow_leaves_local_state_untouched`, `withdraw_refused_when_external_says_no`, and `membership_sync_propagates_to_external_account`. `cascade_cleanup_on_account_and_bank_removal` reordered to run LAST since it deletes the shared test account and would strand later tests. `locked_balance_transactional_protocol` (renamed from `_no_external_write`) updated to match the new lock semantics. Removed the obsolete `drift_clamp_when_external_drops_below_locked` case (no longer reachable under transactional locking).</details> |
| ![bugfix] | `NumismaticsAdapterTests` zeroes the Numismatics `PLAYER` balance via reflection in `perTestReset` — the balance is persistent across `perTestReset` calls and was previously accumulating across test runs. `testOverflowGuard` now uses spur-scaled BankSystem units (`SCALE_FACTOR = 100`) so the overflow assertion matches Numismatics's `nativeScale`. |
