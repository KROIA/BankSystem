## API

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Company foundation — new top-level entity with chunked-NBT persistence and immortal-founder invariant</summary><br>Introduces the `Company` object (immutable name + max supply, mutable description, founder set, bound bank account) and `CompanyManager` (case-insensitive unique-name registry, three-index in-memory lookup, chunked NBT under `data/BankSystem/Companies/`, load-drop-on-missing-account, duplicate-name-on-load keeps older). Founders cannot lose MANAGE on the bound bank account — enforced via a new founder-aware overload of `ServerBankAccount.enforceManageInvariant` and a new `REFUSED_FOUNDER` outcome, wired into `UpdateBankAccountRequest`. Empty defaults for `shareVisuals` / `payoutSchedules` / `totalSharesIssued` persist now so later Company phases (#45/#46/#47) don't need to migrate the NBT schema.</details> |
| ![feature] | New `AsyncCompanyManager` ARRS dispatcher — every `/company` subcommand (`create`, `transfer`, `dissolve`, `description`, `info`) now forwards from a slave to the master via the same async pattern as `AsyncBankManager`. Slaves never touch Company NBT on disk; error paths return typed result codes rendered as the same chat feedback on both sides. |
| ![feature] | <details><summary>Recurring Payouts — Company-scoped worker payout schedules with SQLite audit trail and per-tick scheduler</summary><br>Introduces `PayoutSchedule` (id, target UUID, amount, interval, next-run tick, paused flag, created-at/by) persisted on `Company` NBT alongside a new `nextScheduleId` allocator; `PayoutExecutor` ticks every 20 server ticks (default `PAYOUT_TICK_INTERVAL`), iterates `CompanyManager.forEach`, resolves the target's personal money bank, transfers via `ISyncServerBank.transfer`, writes a `PayoutHistory` row with status `OK` / `INSUFFICIENT_FUNDS` / `TARGET_MISSING`, advances `nextRunTick`. New `PayoutHistoryManager` + `PayoutHistoryRecord` + `sql/PayoutHistory.sql` (indexed on `(company_id, ts DESC)` and `(schedule_id, ts DESC)`). New public `IPayoutManager` interface exposed via `BankSystemAPI.getPayoutManager()` — `createSchedule` / `updateSchedule` / `pauseSchedule` / `deleteSchedule` / `listSchedulesFor` / `getHistory` / `getTotalPaidForSchedule`. Hard-floor of 20 ticks (1s) enforced by create + update. Every payout tick also writes a pair of `TransactionLog.PAYOUT` rows (source `TRANSFER_OUT`-shaped + target `TRANSFER_IN`-shaped). New `PayoutExecutedEvent` fires on the master for every scheduler evaluation (success or failure). `UpdateBankAccountRequest.setUsers` cascade-strips payout schedules whose target was just removed from the Company's bound bank account. Master-only feature — slaves store no payout state.</details> |
| ![feature] | `AsyncCompanyManager`: 6 new payout ARRS functions (create/update/pause/delete/list/history) + company-by-account lookup — routes payout mutations from slave to master under a MANAGE-permission gate and exposes read-only queries (`listSchedulesAsync`, `getHistoryAsync`, `getCompanyInfoByAccountAsync`) for the new UI. |
| ![feature] | <details><summary>Transaction Ledger — new SQLite `TransactionLog` table capturing every deposit / withdraw / transfer</summary><br>Introduces `TransactionLogRecord`, `TransactionLogManager`, and the `sql/TransactionLog.sql` schema (indexed on `(account_number, ts DESC)` and `(company_id, ts DESC)`). Write hooks fire on deposit, withdraw, banknote withdraw, and both transfer legs (source `TRANSFER_OUT` + destination `TRANSFER_IN`). Ledger kinds `PAYOUT` / `DIVIDEND` / `SHARE_STAMP` / `SHARE_REDEEM` / `SHARE_TRADE` are declared now so later Company phases don't need a schema migration. Read API exposes `getByAccount`, `getByCompany`, `getByAccountAndKind`, `getCount` for the future ledger UI. Master-only writes; DB layer generalized from a single hardcoded schema path to a list of schema resources.</details> |
| ![feature] | `AsyncCompanyManager`: new `GET_SHARE_VISUALS` by-id ARRS lookup — slave clients fetch a Company's share visuals + issued / max supply on tooltip cache miss, wiring `ShareVisualCache.tryLookup(int)` so stamped-share tooltips self-heal on the next frame when the initial bulk sync hasn't run (or the id was minted after login). |
| ![feature] | `CompanyManager` gains `stampShare(int)` / `redeemShare(int)` mutators — atomic increment/decrement of `Company.totalSharesIssued` with `maxSupply` cap enforcement and zero floor; each successful call broadcasts `S2CCompanyVisualSupplyUpdatePacket` so all clients update their `ShareVisualCache` supply row live. |
| ![feature] | <details><summary>Company Shares Phase 4c — share ItemID plumbing, holder-index API, `SHARE_TRADE` ledger writes</summary><br>Adds `IBankManager.listAccountsHolding(ItemID)` (and the underlying `ISyncServerBankManager.listAccountsHolding`) — returns the set of account numbers whose item bank for that ItemID currently holds a strictly positive total balance (free + locked). Master-only path; slave returns an empty set until a caller wires ARRS. Used by the upcoming dividend distributor (Task #49) and, later, the StockMarket "Companies" holder-count column. Deposit / withdraw of stamped shares now writes a `TransactionLog.SHARE_TRADE` row (populating `company_id`) instead of a plain `DEPOSIT` / `WITHDRAW` — placeholder settlement hook until a StockMarket match-observer surface exists. New `StampedShareItem.getCompanyIdForItemID(ItemID)` helper resolves a company id from an ItemID template without an ItemStack round-trip. Also ships a new `CompanyShareItemIDTests` suite under the `banksystem:company` category asserting `banksystem:company_id` stays out of the volatile-components set and that two stamped stacks of different companies produce distinct ItemIDs while two of the same company share one.</details> |
| ![feature] | <details><summary>Company Feature Phase 5 — one-shot dividend distributor with all-or-nothing settlement and `DIVIDEND` ledger writes</summary><br>New `DividendPayer` (master-only) resolves a company's stamped-share `ItemID`, snapshots every account holding the share via `IBankManager.listAccountsHolding`, precomputes `total = sum(holderShares) * amountPerShare`, verifies the company's money bank can afford the whole run, then transfers atomically from the company account to each holder's personal money bank. Insufficient funds refuse the run wholesale (no state change). Overflow-safe (`Math.multiplyExact`). Writes paired `TransactionLog.DIVIDEND` rows per holder (outbound on company, inbound on holder), populating `company_id`. New public `IDividendPayer` interface exposed via `BankSystemAPI.getDividendPayer()` with a fail-closed slave shim. New `PayDividendResult` record carries `Reason` (OK / NOT_MASTER / COMPANY_MISSING / INVALID_INPUT / NO_SHARES / INSUFFICIENT_FUNDS / NO_PERMISSION / INTERNAL) plus `totalPaid` + `holderCount`. New `DividendPaidEvent` fires on the master exactly once per successful run.</details> |
| ![feature] | `AsyncCompanyManager`: new `PAY_DIVIDEND` ARRS function routing slave-initiated dividend runs to master under a MANAGE-permission gate — payload carries `companyId` / `amountPerShare` / `includeCompanyAccount` / caller UUID; response carries a typed result code (adds new `CODE_INSUFFICIENT_FUNDS` / `CODE_NO_SHARES`) plus `totalPaid` + `holderCount`. |
| ![feature] | <details><summary>Company Shares Phase 4a — Blank + Stamped Share items with `banksystem:company_id` data component and self-healing tooltip</summary><br>Introduces two new items — `banksystem:blank_share` (inert; shapeless recipe of `paper + leather` → 4× blank) and `banksystem:stamped_share` (carries an identity-relevant integer `banksystem:company_id` data component so two stamped stacks of different companies resolve to distinct `ItemID`s, matching the fungibility model in `CompanyFeature.md §4a`). The `banksystem:company_id` type is registered via a new `BankSystemDataComponents` DeferredRegister and deliberately kept OUT of the volatile-components tag. Right-click is inert on both. New client-side `ShareVisualCache` (companyId → visuals + supply + max) drives the stamped-share tooltip, populated by three new S2C packets — `S2CCompanyVisualUpdatePacket` (broadcast on edit), `S2CCompanyVisualBulkPacket` (initial sync on login — piggybacks the existing `PlayerJoinSyncPacket.send` on master), `S2CCompanyVisualSupplyUpdatePacket` (per-stamp/redeem counter update). Tooltip renders display name in the configured tint, wrapped description, and formatted `Supply: issued / max` line; cache miss shows a grey `Unknown Company Share` placeholder and self-heals on the next frame (mirroring `ItemID.tryUpdateNameCache`). New `SharePresetRegistry` declares 30 preset ids for the editor (`leaf, gear, anvil, pickaxe, sword, shield, crown, star, diamond, emerald, gold_ingot, iron_ingot, wheat, apple, fish, boat, bow, potion, book, map, compass, clock, key, lantern, torch, bell, heart, skull, flame, snowflake`) and shares its allow-list with the server for editor-submission validation. New `CompanyManager.updateShareVisuals(int, ShareVisuals)` mutator with matching ARRS forwarding — `AsyncCompanyManager.UPDATE_SHARE_VISUALS` function is MANAGE-gated on master, validates the preset id against `SharePresetRegistry`, clamps display name (≤24) / description (≤120), and broadcasts the resulting `S2CCompanyVisualUpdatePacket` to all connected clients.</details> |

## CLI

| Tag | Change |
|---:|---|
| ![feature] | New `/company create <name> <maxSupply>` — creates a Company and a bound multi-user bank account with the caller seeded as founder + MANAGE. `maxSupply` bounded to `(0, 1_000_000_000]`. |
| ![feature] | New `/company transfer <companyId> <newFounder>` — reassigns founder role; mirrors MANAGE on the bank account. |
| ![feature] | New `/company dissolve <companyId>` — deletes the Company; the underlying bank account survives as a plain multi-user account. |
| ![feature] | New `/company description <companyId> <text>` — updates the Company's mutable description (MANAGE required). |
| ![feature] | New `/company info <companyId>` — chat printout of Company metadata (id, name, founders, max supply, description, issued count). |
| ![improvement] | <details><summary>`/company` subcommands now take company <em>names</em> instead of internal ids, with rights-scoped tab-completion</summary><br>`/company transfer`, `dissolve`, `description`, and `info` accept `<companyName>` in place of `<companyId>` — the internal id was a leaky implementation detail. Tab-completion is filtered per subcommand by the caller's rights: `info` lists every company on the server, `description` lists only companies where the caller has MANAGE on the bound bank account, and `transfer` / `dissolve` list only companies where the caller is a founder. Suggestions are ARRS-forwarded to master on slaves via a new `AsyncCompanyManager.LIST_COMPANIES_FOR_CALLER` function — no client-side cache to invalidate. Name resolution is case-insensitive; unknown names emit a localised "No such company" error instead of a stack trace.</details> |

Bound to a Company via `/company stamper-bind <pos> <companyName>` and cleared via `/company stamper-unbind <pos>` — both MANAGE-gated.
