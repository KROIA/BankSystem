## API

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Company foundation — new top-level entity with chunked-NBT persistence and immortal-founder invariant</summary><br>Introduces the `Company` object (immutable name + max supply, mutable description, founder set, bound bank account) and `CompanyManager` (case-insensitive unique-name registry, three-index in-memory lookup, chunked NBT under `data/BankSystem/Companies/`, load-drop-on-missing-account, duplicate-name-on-load keeps older). Founders cannot lose MANAGE on the bound bank account — enforced via a new founder-aware overload of `ServerBankAccount.enforceManageInvariant` and a new `REFUSED_FOUNDER` outcome, wired into `UpdateBankAccountRequest`. Empty defaults for `shareVisuals` / `payoutSchedules` / `totalSharesIssued` persist now so later Company phases (#45/#46/#47) don't need to migrate the NBT schema.</details> |
| ![feature] | New `AsyncCompanyManager` ARRS dispatcher — every `/company` subcommand (`create`, `transfer`, `dissolve`, `description`, `info`) now forwards from a slave to the master via the same async pattern as `AsyncBankManager`. Slaves never touch Company NBT on disk; error paths return typed result codes rendered as the same chat feedback on both sides. |
| ![feature] | <details><summary>Transaction Ledger — new SQLite `TransactionLog` table capturing every deposit / withdraw / transfer</summary><br>Introduces `TransactionLogRecord`, `TransactionLogManager`, and the `sql/TransactionLog.sql` schema (indexed on `(account_number, ts DESC)` and `(company_id, ts DESC)`). Write hooks fire on deposit, withdraw, banknote withdraw, and both transfer legs (source `TRANSFER_OUT` + destination `TRANSFER_IN`). Ledger kinds `PAYOUT` / `DIVIDEND` / `SHARE_STAMP` / `SHARE_REDEEM` / `SHARE_TRADE` are declared now so later Company phases don't need a schema migration. Read API exposes `getByAccount`, `getByCompany`, `getByAccountAndKind`, `getCount` for the future ledger UI. Master-only writes; DB layer generalized from a single hardcoded schema path to a list of schema resources.</details> |

## CLI

| Tag | Change |
|---:|---|
| ![feature] | New `/company create <name> <maxSupply>` — creates a Company and a bound multi-user bank account with the caller seeded as founder + MANAGE. `maxSupply` bounded to `(0, 1_000_000_000]`. |
| ![feature] | New `/company transfer <companyId> <newFounder>` — reassigns founder role; mirrors MANAGE on the bank account. |
| ![feature] | New `/company dissolve <companyId>` — deletes the Company; the underlying bank account survives as a plain multi-user account. |
| ![feature] | New `/company description <companyId> <text>` — updates the Company's mutable description (MANAGE required). |
| ![feature] | New `/company info <companyId>` — chat printout of Company metadata (id, name, founders, max supply, description, issued count). |
| ![improvement] | <details><summary>`/company` subcommands now take company <em>names</em> instead of internal ids, with rights-scoped tab-completion</summary><br>`/company transfer`, `dissolve`, `description`, and `info` accept `<companyName>` in place of `<companyId>` — the internal id was a leaky implementation detail. Tab-completion is filtered per subcommand by the caller's rights: `info` lists every company on the server, `description` lists only companies where the caller has MANAGE on the bound bank account, and `transfer` / `dissolve` list only companies where the caller is a founder. Suggestions are ARRS-forwarded to master on slaves via a new `AsyncCompanyManager.LIST_COMPANIES_FOR_CALLER` function — no client-side cache to invalidate. Name resolution is case-insensitive; unknown names emit a localised "No such company" error instead of a stack trace.</details> |
