## Performance

| Tag | Change |
|---:|---|
| ![improvement] | <details><summary>Balance history now records on change only, with a one-hour heartbeat — idle accounts stop accumulating one row every minute</summary><br>Before this change, the server wrote one balance-history row per bank per snapshot tick (default: every minute) regardless of whether anything moved. An account sitting untouched for a day burned 1 440 rows per item just to say "still the same value." The recorder now compares each candidate row against the last saved (balance, locked balance) for that account/item and skips duplicates, emitting a heartbeat row at most once per hour so long-idle series still have a floor. Databases from earlier versions self-heal on first boot after upgrading — the first retention sweep runs before the first snapshot, so the old flat 1 440-row histories compact into the tiered plan immediately.</details> |
| ![feature] | <details><summary>Tiered retention plan supersedes the flat 24-hour history cap — full resolution stays for the last day, and coarser buckets keep up to a year of context</summary><br>Balance history is now retained in age bands: full resolution for the last 24 hours, one row per 15-minute bucket from 24 hours to 7 days, one row per hour from 7 to 30 days, one row per day from 30 days to a year, and hard-pruned beyond a year. A sixty-minute sweep applies each band idempotently, and the same server also runs one sweep synchronously on start so upgrading from v2.0.6 or earlier trims existing 1 440-row histories in one pass. Storage math: the old design accumulated 14 400 rows per account for 24 hours of coverage; the new design holds about 15 000 rows per account for a **full year** at graceful resolution. Two new settings — `BALANCE_SNAPSHOT_HEARTBEAT_MINUTES` (default 60) and `BALANCE_HISTORY_RETENTION_SWEEP_MINUTES` (default 60) — expose the heartbeat and sweep cadence.</details> |
| ![improvement] | The Balance History chart now asks the server for a bucketed downsample capped at 500 samples per item series, so the payload no longer grows linearly with world age. The chart draws a straight line across empty buckets, so a "7d" view on an account with only a day of activity still frames the full week with the data on the right edge. |
| ![deprecation] | `BALANCE_SNAPSHOT_MAX_RECORDS_PER_ITEM` is deprecated and no longer enforced — the tiered retention plan replaces it. Existing values in `settings.json` are kept for backward compatibility and produce a one-shot warning at server start if set to a non-zero value. |

## CLI

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>New `/banksystem backup` op-only subcommands — `pause`, `resume`, `status`, and `snapshot <path>` — for safe external world backups</summary><br>External backup scripts (like `mc_backup.sh` on Ubuntu) previously had no way to guarantee that `banksystem.db` was in a consistent state while a `tar` was in flight — the database worker could commit at any moment during the archive. Four new op-only subcommands close the gap. `pause` blocks the single-threaded database worker until `resume` is called, emitting a distinctive `[BankSystem] db-worker paused for backup` log line that external scripts can tail-and-grep for as an acknowledgement. A safety timer auto-resumes after 120 seconds so a forgotten pause can never soft-lock the server. `snapshot <path>` uses SQLite's `VACUUM INTO` to produce a lock-free consistent copy of the database at an arbitrary path — writers stay live, no pause needed. `status` reports whether the worker is currently paused. All four require permission level 2 (op).</details> |
| ![removal] | The dev-only `/banksystem testScreen` command has been removed. It was only ever a developer aid for GUI testing and had been marked "remove before release" since v2.0. |

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Balance History chart gains six timescale buttons — `1h / 6h / 1d / 7d / 30d / All` — in the top-left of the frame</summary><br>Click a button to reframe the chart to that window in one click, replacing the manual pan-and-zoom workflow. Each button asks the server for a bucketed downsample of at most 500 samples per item series over the selected range, so the payload stays lean regardless of world age or how long the account has been active. The viewport always spans the requested window rather than snapping to the received-data extents, so clicking "7d" on a world that only has a day of history still shows a seven-day-wide chart with the data pushed to the right edge — you see the range you asked for, not just the range that happens to be populated. Layout, button colors, and the "active" highlight mirror StockMarket's candlestick-chart toolbar for consistency.</details> |
| ![feature] | <details><summary>Seven new banknote denominations — 5000, 10000, 20000, 50000, 100000, 500000, 1000000 — with a full crafting chain in both directions</summary><br>Large withdrawals no longer bury players in stacks of $1000 notes. The new tier extends the existing lineup with a distinct color per bill (navy 5k, teal 10k, crimson 20k, bronze 50k, dark green 100k, magenta 500k, gold 1M) and slots into the ATM screen automatically. Both directions are shapeless: forward recipes step up cleanly at exact ratios (5×1k = 5k, 2×5k = 10k, 2×10k = 20k, 5×10k = 50k, 5×20k = 100k, 5×100k = 500k, 2×500k = 1M) with no crafting inflation, and each new bill has a matching break-down recipe so players can make change back down to $1000 notes. All seven are default-blacklisted for direct banking (they only act as physical currency, exactly like the existing $5–$1000 notes).</details> |
| ![improvement] | The ATM screen's denomination grid uses tighter spacing so the full lineup (now 20 rows including the new 5k–1M notes) fits on one page without scrolling. |
| ![feature] | <details><summary>Complete crafting network for every money and coin denomination — you can now craft directly between any two related tiers</summary><br>The recipe book previously had big gaps: cents had no crafting recipes at all, no bridge existed between coins and the $1 bill, and the new 5k–1M tier only linked to its immediate neighbour. 56 new shapeless recipes fill the network — every larger denomination breaks down into every smaller one whose split fits a single crafting slot (ratio ≤ 64), and every target has forward recipes for the natural 2×half / 5×fifth / 4×quarter / mixed-halves combinations. Highlights: 2×50k = 100k, 2×20k + 10k = 50k, 2×cent50 = $1, 5×cent20 = $1, 2×cent20 + cent50 + cent10 = $1, plus the full break-down chain from $1M all the way down to any coin whose split fits. All recipes are exact — no crafting inflation anywhere.</details> |
| ![bugfix] | The legacy "break a $1000 into $20 bills" recipe returned 20 bills instead of 50, silently burning 60% of the note's value on each craft. Now returns the correct 50 bills. |
| ![bugfix] | Selecting a bank account that has no money slot in the ATM now correctly shows "Available for withdrawal: 0" instead of keeping the previous account's balance on screen, and the warning color on the requested-sum label updates accordingly. |
| ![feature] | <details><summary>New Money Converter tab in the ATM lets you deposit banknotes into a temporary cache, then withdraw any combination of denominations totaling the same amount</summary><br>The ATM screen now has two tabs — the classic **Withdraw** tab and a new **Convert** tab — with the account selector docked between them in the top row so both tabs share it. On the Convert tab, click **Deposit money** to sweep every banknote and coin from your inventory into a per-player temporary cache. From there you can withdraw any mix of denominations up to the cached total: the same +N/-N/text-input controls the Withdraw tab uses, no bank account touched. Withdrawing the exact cached amount leaves the cache at zero; withdrawing less lets you either use the one-click **Deposit remainder to bank** button (routes through the normal deposit path on any account you have permission for, complete with balance history and change-stream updates) or **Drop remainder** to receive the leftover as the smallest possible bundle of bills at your feet.<br><br>Both tabs now gray out denominations you can't currently afford — the Withdraw tab against the selected account balance, the Convert tab against the cache — with an **Insufficient balance** tooltip on hover, and the +N buttons for those rows are disabled. Text-input entries are clamped to the max affordable so you can't overshoot.<br><br>If you close the ATM screen or disconnect with a nonzero cache, the remainder is automatically dropped at the ATM as a minimum-item split so nothing is lost. Every ATM button now has a hover tooltip explaining what it does, anchored so top-row tooltips render below the cursor and bottom-row above to avoid covering the button.</details> |
| ![improvement] | <details><summary>The Bank Terminal's bank-list column count now adapts to the available width — small GUI scales and wide monitors unlock more columns, and JEI's narrower panel is respected automatically</summary><br>The column count was previously hardcoded at 1 (with JEI installed) or 2 (without), which wasted horizontal space on low GUI scales and forced JEI users on wide monitors into a single column no matter how much room they had. The list now measures its own available width each layout pass and picks a column count that keeps every row wide enough for its +/- amount buttons to stay comfortably clickable — from 1 column on a narrow panel up to a hard cap of 6 for readability. Adjustments take effect immediately on window resize and on any change to Minecraft's GUI scale, no relog needed.</details> |
