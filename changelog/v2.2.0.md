## Security

| Tag | Change |
|---:|---|
| ![hardening] | A Share Stamper bound to one company can no longer be re-bound to another company without unbinding it first |
| ![hardening] | A bound Share Stamper can only be used by players who may manage its company (or BankSystem admins); losing that right closes the open stamper screen |
| ![bugfix] | Balance history is now only sent to members of the account and to BankSystem admins; previously any player could request the history of any account |
| ![feature] | Admin commands and admin functions can now be granted per player with permission nodes (e.g. LuckPerms): `banksystem.admin.command.trust`, `.op`, `.backup`, `.symbols`, `.exportrecipes`, `banksystem.admin.adminmode`, `banksystem.admin.software`. Without a permission mod, operator level 2 is required, as before |
| ![hardening] | Players can only load the data of bank accounts they are a member of; this now covers every way to read account data (balances, members, permissions and account details), and BankSystem admins can still see every account. Player lists in pickers now contain only player names |
| ![hardening] | Looking up another player's details, or whether they are a BankSystem admin, now only returns their name unless you are an admin |
| ![hardening] | The payout target picker no longer shows other players' account permissions |
| ![hardening] | Using the Banking Software on another player now also requires BankSystem admin rights |
| ![breaking] | Multi-server: on slave servers that are not trusted yet, display blocks show no data and BankSystem admin mode in `/banksystem manage` and `/bank manage` is not available until the slave is trusted with `/banksystem trust` |
| ![feature] | New permission node `banksystem.admin` (without a permission mod it falls back to operator level 2) and a new optional setting "Sync admin flag with LuckPerms" in Mod Settings → Integrations (off by default): with LuckPerms installed, `/banksystem op` and `/banksystem deop` also grant or remove the `banksystem.admin` permission, and granting or removing that permission in LuckPerms immediately makes the player a BankSystem admin or removes their admin rights. Existing BankSystem admins are copied to LuckPerms once when the setting is first turned on. Untrusted slave servers never change admin rights |
| ![feature] | Admin audit trail: every admin action (balance set/add/remove, unlocks, account edits, freezes, disallowed items, banks closed by an admin, balances destroyed because they could not be handed to a user an admin deleted) is written to a daily file in `<world>/data/BankSystem/audit/` on the master server and sent as a chat alert to online BankSystem admins, also on slave servers. `/banksystem alerts on\|off` lets each admin mute or unmute the chat alerts; the setting "Admin alerts on by default" decides for admins who never used it. The audit files are always written |
| ![feature] | Suspicious-activity flags: the master now flags banknote deposits of money the depositor did not withdraw themselves, very large withdrawals, sudden wealth jumps, large transfers, payouts or dividends into newly created accounts, a total money supply of all accounts that grows by more than 10% and more than $10,000,000 within an hour, and a banknote withdrawal on a slave server whose delivery could not be confirmed. Each flag is stored, written to the audit file and sent to admins as an alert; every check has its own on/off switch and thresholds (wealth jumps and money supply also a cooldown) in the new "Suspicious activity" settings, except the unconfirmed withdrawal, which is always on. Bank accounts now remember when they were created; accounts from older versions take the date of their first recorded activity |
| ![feature] | Daily audit digest: the master writes a short markdown summary of the previous day (money supply, top cash gainers, every flag, admin actions) to the audit folder, once per day. `/banksystem auditreport <hours>` writes one for the last 1 to 720 hours on demand and shows the file path |
| ![hardening] | Requests to the bank server, from a slave server or from the game, that get no answer in time or are cut off by a disconnect or a failed send no longer hang forever; they now fail. Bank transfers wait up to 30 seconds. Audit and history pages, the server network overview, company actions and admin commands wait up to 150 seconds, so a busy server or a running backup does not cut them off. Bank Download blocks keep working instead of getting stuck until their chunk reloads or the server restarts, Bank Upload blocks and terminal crafting give the item back instead of losing it, bank displays and their history try again, and Mod Settings shows the failure instead of loading forever. Admin commands report that the request to the master failed, and company screens and commands report that the bank server did not answer, instead of staying silent. When a dividend or catch-up payment gets no answer, the screen now says it may have gone through and keeps the Pay button off instead of reporting a failure |
| ![hardening] | Multi-server: deposits, withdrawals, converter deposits and banknote withdrawals between slave servers and the master are applied at most once, even if a request arrives twice. When such a transfer fails without a clear answer, the server that sent it asks the other server whether it went through and only gives the money or items back if it did not. A transfer whose outcome still cannot be confirmed is not refunded but logged, and an unconfirmed banknote withdrawal is flagged for admins. Bank terminal crafting and the Bank Download block keep items locked, instead of releasing them, when the master cannot confirm that it took them |

## API

| Tag | Change |
|---:|---|
| ![feature] | Placeholder support for TAB and Placeholder API: player balances, money in circulation, account counts and a richest-players list. On slave servers that are not trusted yet, the placeholder leaderboards show no data until the slave is trusted with `/banksystem trust` |
| ![feature] | New public money formatting helper so add-ons can display money exactly like BankSystem does |
| ![removal] | The configurable TAB placeholder identifiers were replaced by fixed placeholder names; old settings are ignored |
| ![feature] | Full transaction ledger: every balance change is now recorded, including deposits and withdrawals at terminals, upload/download blocks, the converter and crafting, transfers, admin edits, closed banks, user deletions (balances handed to the player, or destroyed when they could not be handed out, with the reason), starting balances, payouts, dividends, share movements and StockMarket trades. Each entry has a stable numeric type code, who caused it (player, admin, console, system or StockMarket) and the bank balance afterwards. On multi-server networks the master records every entry; slave servers send the entry type with each bank request, and unexpected types are recorded as unknown and reported in the log |
| ![feature] | New `getLedger()` API so add-ons can write their own ledger entries, and StockMarket can record trades with order reference, money, price and the virtual-liquidity quantity |
| ![improvement] | Transfers are now one entry type with a signed amount (negative for the sender). Existing ledger entries are upgraded automatically on first start and stay readable |
| ![feature] | New suspicion-flag table and a single call for add-ons and future checks to raise a flag; each flag is stored, written to the audit file and sent to admins as an alert |
| ![feature] | Account freeze API: add-ons can check and set whether an account is frozen (also from slave servers) and get an event whenever an account is frozen or unfrozen. Blocked bank calls return the new status `FAILED_ACCOUNT_FROZEN` |
| ![bugfix] | Multi-server: bank requests from slave servers no longer wait forever when the master's reply fails or is empty; the add-on that made the request now gets the error |
| ![feature] | New "transaction logged" event: add-ons are notified of every entry written to the transaction ledger, with account, type, item, amount, who caused it, counterparty account, company, time and note |
| ![feature] | New "suspicious activity flagged" event: add-ons are notified whenever a suspicion flag is raised, with the flag name, severity, amount and details. Both new events fire only on the master or standalone server, on the thread that wrote the entry |
| ![feature] | New `getNoteFlowLog()` API so add-ons can record money notes they create or destroy outside the bank (for example StockMarket villager trades) in the diagnostics file; for a villager trade it also records the villager's ID, dimension and block position. It works on every server, including slaves, and never blocks or throws |
| ![bugfix] | Deleting a user through the API no longer duplicates the balance of a company account that loses its last member; the company account is now kept with its balance and nothing is paid out for it. On multi-server networks the payout to the player is tried on each slave server in turn with what is still left, and items that could not be handed out are recorded in the ledger as destroyed, with the reason (player offline or outcome unknown) |

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | Screens with a Save or Apply button now ask whether to save or discard unsaved changes before closing: Bank Download, Bank Account Management (also when switching accounts), Mod Settings, Display block settings, Payout editor, Share visual editor and the Company Overview tab (also when switching tabs). In Bank Download the Save button also turns amber while there are unsaved changes and goes back to normal after Save or Discard, or when you undo your edits by hand |
| ![improvement] | Bank Download: without a connected bank, the Connect button is shown in orange and flashes when you try something that needs a bank |
| ![improvement] | Pressing Esc on a confirmation popup now returns to the previous screen instead of closing everything |
| ![bugfix] | Unbinding a Share Stamper now ejects everything in it (blank and stamped shares) on top of the block instead of leaving it inside |
| ![bugfix] | Bank Display item icons (balance overview and balance history legend) no longer go missing on the display or in its right-click screen; icons also keep their item details |
| ![feature] | The Bank Account Management screen has a new History button that opens the balance history of the selected account. Admins can use it to inspect any player's account, or open the history of any account with `/banksystem history <player\|account>` or the History button in the audit screen; for admins, suspicion flags appear as markers on the chart with their type and details on hover |
| ![improvement] | The company Statistics tab shows only the share count and number of holders to shareholders who are not members of the company account; members see the financials but not who the other shareholders are, and admins see everything |
| ![improvement] | On slave servers that are not trusted yet, the Bank Account Management and currency binding screens open read-only with a note explaining that changes are disabled until an admin runs `/banksystem trust`; previously edits were silently discarded |
| ![feature] | Admins can freeze a bank account with `/banksystem freeze <account> [on\|off]` or the new Freeze button in Bank Account Management. A frozen account blocks every player deposit, withdrawal, transfer (in or out), converter, upload/download block, crafting and payout/dividend from it; players see a message and keep their items. Admin edits still work, and every freeze is recorded in the transaction ledger |
| ![feature] | New admin audit screen, opened with `/banksystem audit <player\|account>`: the account's ledger entries with time, type, item, signed amount, counterparty, actor, note and reference, filtered by type and time range and loaded 100 entries per page |
| ![feature] | Whole-server balance history: a new **Server history** button in `/banksystem manage` shows every item summed over all accounts (admins only) |
| ![bugfix] | Bank Download block: when taking items out of the bank fails, the items it had already placed into the block are taken back out, so the block no longer keeps items the account was never charged for. If a hopper already took some of them out, only the part that came back is released in the bank; the rest stays locked for an admin to check. The Bank Terminal does the same for items the player already took out |
| ![bugfix] | Balance history chart: zooming in can no longer shrink the time axis until both edges show the same time (the smallest view is now one minute), a too-small zoom is no longer remembered as the zoom-out limit when the chart is reopened, and Ctrl+Space always jumps back to a normal time range ending at the current time |
| ![bugfix] | Multi-server: on slave servers, depositing the ATM converter balance into a bank account now adds the full amount to the account's money balance, the same as on a single server. Before, most of the amount came back into the converter as refused, and up to 4 whole units were booked as cents (4.00 became 0.04), so up to 3.96 was lost per deposit. A converter deposit that the master refuses or that could not be sent is no longer lost; it goes back into the converter. If the master's answer is lost, the slave asks the master whether the deposit went through: if not, the money goes back into the converter; if it did, the deposit counts as done. Only if this still cannot be confirmed, nothing is refunded (so money cannot be duplicated) and the deposit is logged for admins to check |
| ![improvement] | Bank Download: every part of a withdraw condition row now has a tooltip that explains it (item, bank balance, amount, condition and each of its options, condition value and the remove button); the item name is now shown in the item's tooltip. These tooltips open beside the cursor on the side with more room, wrap long text and always stay on screen |
| ![feature] | New **Integrations** group in Mod Settings that collects the optional mod integrations. Each one is a collapsible section: the check box in its header is the on/off switch, and a click on the header shows a short description and the integration's own settings. Placeholders (on by default, takes effect after a restart, shown by a restart marker) holds the refresh intervals, richest-players list size and money format, which are greyed out while it is off; further sections cover LuckPerms admin sync, Numismatics and Lightman's Currency (both on by default, take effect immediately) and the Discord feed (off by default), whose description lists the message types and where to set up the webhooks. Switching off Numismatics or Lightman's Currency works as if the mod were not installed, also for add-ons that look up the currency providers: bound balances stay in that mod's account, untouched, and are available again as soon as the switch is turned back on |
| ![bugfix] | Unbinding a currency from Numismatics or Lightman's Currency while that mod is missing or switched off is now refused as long as locked money or leftover fractions are still held for it; previously that money was set to zero and lost |
| ![feature] | Discord feed: the master server (or a single server) can post bank events to Discord webhooks. It is off by default and switched on in Mod Settings → Integrations. Webhook URLs go into `config/modutilities/discord/webhooks.json`; `config/modutilities/discord/banksystem.json` picks for each message type the webhooks it goes to and a minimum amount, plus the message language (English, German, Swiss German or Chinese). Every message type starts disabled. `/banksystem discord reload` (same as `/modutilities discord reload`) applies changes, and `/banksystem discord status` shows the webhook names and whether they are valid, plus each message type's on/off state, minimum amount and webhooks, never the webhook URLs; both need operator level 3 or the permission `modutilities.command.discord`. Ten message types: deposits, withdrawals, incoming and outgoing transfers, payouts, dividends, share movements (stamping, redeeming and share trades), admin actions (including account freezes), suspicious-activity flags and other bank actions. To protect players' privacy, each message names only the player, plus the item, amount, company and time; admins can add the account number, player UUID and counterparty account back with their own field list in `banksystem.json`. Amounts are shown formatted: money as `1'500.00`, other items without forced decimals (`3`, `1'500`, `2.50`). Suspicious-activity flags also show the flagged account, so they belong in an admin-only channel. Slave servers never post, so every event is posted once. Stock market trades are left out because StockMarket has its own feed; a company payout is posted once, for the receiving account; a dividend run or an item disallow posts one summary with the total amount and the number of holders instead of one message per holder |
| ![bugfix] | Bank Terminal: if one item in a player's terminal slots can no longer be loaded (for example because its mod was removed), the items in all later slots are no longer lost; the unreadable item is skipped with a warning in the server log and every other item is kept |
| ![bugfix] | Bank Upload block: when a deposit fails, the items go back into the block without replacing items that a hopper or player put into that slot in the meantime; they are added to that stack, moved to another free slot, or dropped at the block if there is no room |

| ![feature] | In-game tests for the suspicious-activity flags: each flag at and just below its threshold, banknote netting and refunds, the wealth-jump cooldown, the age of new and older accounts, and the on/off switches |
| ![feature] | In-game tests for the whole-server history sums, the money-supply flag and its cooldown, the audit digest content and once-per-day rule, the report path and hour limits, and admin-only flag markers |
| ![bugfix] | Stopping a server no longer loses ledger entries, balance history snapshots and other database writes that were still queued; the database now finishes every queued write before it closes, checked by a new in-game test |
| ![feature] | LuckPerms tests for the admin sync: `-Pwith_luckperms=true` loads LuckPerms in dev runs only (never bundled). New suites cover op/deop writes, live LuckPerms changes, group-wins and migration, plus a save that ran with LuckPerms and is reloaded without it (flags kept, op/deop still work) |
| ![feature] | In-game tests that a failed or empty deposit reply from the master is never read as a full deposit, and that a failed bank request reaches the caller instead of hanging |
| ![feature] | In-game tests for the new transaction and suspicion events: one event per ledger entry (single and batch writes) with all its fields, and one event per raised flag |
| ![feature] | In-game tests for the Integrations settings: converting old settings files, the Numismatics and Lightman's Currency switches, and refused unbinds while locked money or leftover fractions are held |
| ![feature] | In-game tests for the Discord feed: one message per ledger entry, formatted amounts for money and other items, incoming and outgoing transfers, payouts posted for the recipient only, merged dividend summaries, nothing posted while the feed is off, suspicion flags, a config file that lists every message type, default messages in every language that name the player without account, UUID or counterparty (suspicion flags keep the account), and nothing posted from a slave server |
| ![bugfix] | A failed disk write (for example on a full or read-only disk) while saving bank accounts, the item registry, companies or currency bindings was counted as a successful save and not retried until the next forced save; the save now stays pending and is retried at the next auto-save, checked by new in-game tests |
| ![feature] | New diagnostics file `data/BankSystem/Database/banksystem_diagnostics.db` in the world folder on every server (master, slaves and single servers) for an external audit tool. It records when the bank accounts were last saved; on slave servers, a transfer journal with every step of each transfer of value to or from the master (requested, confirmed, delivered, returned or timed out) for bank requests, converter deposits and item drops; and on every server, a note-flow log of money notes created or destroyed outside the bank, for now notes put into or taken out of the ATM converter, plus notes recorded by add-ons, where villager trades also store the villager's ID, dimension and block position. Each transfer to or from the master has a transfer ID, and the master's transaction ledger entries for it carry the same ID as the slave's journal, so an audit tool can match both sides. BankSystem only writes to it, on its own background thread, and never reads it back, so it is safe to delete; a damaged file is renamed and replaced. Checked by in-game tests |
| ![feature] | 22 of the in-game test suites (231 tests) now also run without starting Minecraft, as part of the developer build, in about 10 seconds; the automated test runner can run them there instead of in game. Release builds still contain no tests |
