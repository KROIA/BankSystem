## Security

| Tag | Change |
|---:|---|
| ![hardening] | A Share Stamper bound to one company can no longer be re-bound to another company without unbinding it first |
| ![hardening] | A bound Share Stamper can only be used by players who may manage its company (or BankSystem admins); losing that right closes the open stamper screen |
| ![bugfix] | Balance history is now only sent to members of the account and to BankSystem admins; previously any player could request the history of any account |
| ![feature] | Admin commands and admin functions can now be granted per player with permission nodes (e.g. LuckPerms): `banksystem.admin.command.trust`, `.op`, `.backup`, `.symbols`, `.exportrecipes`, `banksystem.admin.adminmode`, `banksystem.admin.software`. Without a permission mod, operator level 2 is required, as before |
| ![hardening] | Players can only load the data of bank accounts they are a member of; this now covers every way to read account data (balances, members, permissions and account details), and BankSystem admins can still see every account. Player lists in pickers now contain only player names |
| ![hardening] | Looking up another player's details, or whether they are a BankSystem admin, now only returns their name unless you are an admin |
| ![hardening] | The payout target picker no longer shows other players' account permissions |
| ![hardening] | Using the Banking Software on another player now also requires BankSystem admin rights |
| ![breaking] | Multi-server: on slave servers that are not trusted yet, placeholder leaderboards and display blocks show no data and BankSystem admin mode in `/banksystem manage` and `/bank manage` is not available until the slave is trusted with `/banksystem trust` |
| ![feature] | New optional setting "Sync admin flag with permission" (off by default): with LuckPerms installed, `/banksystem op` and `/banksystem deop` also grant or remove the `banksystem.admin` permission, and granting or removing that permission in LuckPerms immediately makes the player a BankSystem admin or removes their admin rights. Existing BankSystem admins are copied to LuckPerms once when the setting is first turned on. Untrusted slave servers never change admin rights |
| ![feature] | New permission node `banksystem.admin`; without a permission mod it falls back to operator level 2 |
| ![feature] | Admin audit trail: every admin action (balance set/add/remove, unlocks, account edits, freezes, disallowed items, banks closed by an admin) is written to a daily file in `<world>/data/BankSystem/audit/` on the master server and sent as a chat alert to online BankSystem admins, also on slave servers |
| ![feature] | Suspicious-activity flags: the master now flags banknote deposits of money the depositor did not withdraw themselves, very large withdrawals, sudden wealth jumps and large transfers, payouts or dividends into newly created accounts. Each flag is stored, written to the audit file and sent to admins as an alert; every check has its own on/off switch and thresholds in the new "Suspicious activity" settings |
| ![feature] | `/banksystem alerts on\|off` lets each admin mute or unmute the chat alerts; the new setting "Admin alerts on by default" decides for admins who never used it. The audit files are always written |
| ![feature] | Money-supply alert: the master flags when the total money of all accounts grows by more than 10% and more than $10,000,000 within an hour (both adjustable, with a cooldown and an on/off switch) |
| ![feature] | Daily audit digest: the master writes a short markdown summary of the previous day (money supply, top cash gainers, every flag, admin actions) to the audit folder, once per day. `/banksystem auditreport <hours>` writes one for the last 1 to 720 hours on demand and shows the file path |

## API

| Tag | Change |
|---:|---|
| ![feature] | Placeholder support for TAB and Placeholder API: player balances, money in circulation, account counts and a richest-players list |
| ![feature] | New public money formatting helper so add-ons can display money exactly like BankSystem does |
| ![removal] | The configurable TAB placeholder identifiers were replaced by fixed placeholder names; old settings are ignored |
| ![feature] | Full transaction ledger: every balance change is now recorded, including deposits and withdrawals at terminals, upload/download blocks, the converter and crafting, transfers, admin edits, closed banks, starting balances, payouts, dividends, share movements and StockMarket trades. Each entry has a stable numeric type code, who caused it (player, admin, console, system or StockMarket) and the bank balance afterwards. On multi-server networks the master records every entry; slave servers send the entry type with each bank request, and unexpected types are recorded as unknown and reported in the log |
| ![feature] | New `getLedger()` API so add-ons can write their own ledger entries, and StockMarket can record trades with order reference, money, price and the virtual-liquidity quantity |
| ![improvement] | Transfers are now one entry type with a signed amount (negative for the sender). Existing ledger entries are upgraded automatically on first start and stay readable |
| ![improvement] | Bank accounts now remember when they were created; accounts from older versions take the date of their first recorded activity |
| ![feature] | New suspicion-flag table and a single call for add-ons and future checks to raise a flag; each flag is stored, written to the audit file and sent to admins as an alert |
| ![feature] | Account freeze API: add-ons can check and set whether an account is frozen (also from slave servers) and get an event whenever an account is frozen or unfrozen. Blocked bank calls return the new status `FAILED_ACCOUNT_FROZEN` |
| ![bugfix] | Multi-server: bank requests from slave servers no longer wait forever when the master's reply fails or is empty; the add-on that made the request now gets the error |

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | Screens with a Save or Apply button now ask whether to save or discard unsaved changes before closing: Bank Download, Bank Account Management (also when switching accounts), Mod Settings, Display block settings, Payout editor, Share visual editor and the Company Overview tab (also when switching tabs) |
| ![improvement] | Bank Download: without a connected bank, the Connect button is shown in orange and flashes when you try something that needs a bank |
| ![improvement] | Pressing Esc on a confirmation popup now returns to the previous screen instead of closing everything |
| ![bugfix] | Unbinding a Share Stamper now ejects everything in it (blank and stamped shares) on top of the block instead of leaving it inside |
| ![bugfix] | Bank Display item icons (balance overview and balance history legend) no longer go missing on the display or in its right-click screen; icons also keep their item details |
| ![feature] | The Bank Account Management screen has a new History button that opens the balance history of the selected account; admins can use it to inspect any player's account |
| ![bugfix] | The company Overview tab now shows the company account name to shareholders who are not members of that account |
| ![improvement] | The company Statistics tab shows only the share count and number of holders to shareholders who are not members of the company account; members see the financials but not who the other shareholders are, and admins see everything |
| ![improvement] | On slave servers that are not trusted yet, the Bank Account Management and currency binding screens open read-only with a note explaining that changes are disabled until an admin runs `/banksystem trust`; previously edits were silently discarded |
| ![feature] | Admins can freeze a bank account with `/banksystem freeze <account> [on\|off]` or the new Freeze button in Bank Account Management. A frozen account blocks every player deposit, withdrawal, transfer (in or out), converter, upload/download block, crafting and payout/dividend from it; players see a message and keep their items. Admin edits still work, and every freeze is recorded in the transaction ledger |
| ![feature] | New admin audit screen, opened with `/banksystem audit <player\|account>`: the account's ledger entries with time, type, item, signed amount, counterparty, actor, note and reference, filtered by type and time range and loaded 100 entries per page |
| ![feature] | Whole-server balance history: a new **Server history** button in `/banksystem manage` shows every item summed over all accounts (admins only) |
| ![feature] | Admins can open the balance history of any account with `/banksystem history <player\|account>` or the new History button in the audit screen; suspicion flags appear as markers on the chart with their type and details on hover |
| ![bugfix] | Bank Account Management: the Freeze button no longer overlaps the Save Changes button; the account selector gets narrower instead when space runs out |
| ![bugfix] | Bank Download block: when taking items out of the bank fails, the items it had already placed into the block are taken back out, so the block no longer keeps items the account was never charged for |
| ![bugfix] | Balance history chart: zooming in can no longer shrink the time axis until both edges show the same time (the smallest view is now one minute), a too-small zoom is no longer remembered as the zoom-out limit when the chart is reopened, and Ctrl+Space always jumps back to a normal time range ending at the current time |
| ![bugfix] | Multi-server: on slave servers, a converter deposit that could not be sent to the master was counted as deposited and the money was lost; it now goes back into the converter. If the master's answer is lost and the outcome is unknown, nothing is refunded (so money cannot be duplicated) and the deposit is logged for admins to check |
| ![improvement] | Bank Download: every part of a withdraw condition row now has a tooltip that explains it (item, bank balance, amount, condition and each of its options, condition value and the remove button); the item name is now shown in the item's tooltip |
| ![improvement] | Bank Download: the Save button turns amber while there are unsaved changes and goes back to normal after Save or Discard, or when you undo your edits by hand |
