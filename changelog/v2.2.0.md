## Security

| Tag | Change |
|---:|---|
| ![hardening] | A Share Stamper bound to one company can no longer be re-bound to another company without unbinding it first |
| ![hardening] | A bound Share Stamper can only be used by players who may manage its company (or BankSystem admins); losing that right closes the open stamper screen |
| ![hardening] | Hand-edited values in settings.json are now checked against the same limits as the in-game Mod Settings screen when the server loads them; out-of-range values are corrected and each correction is logged |
| ![bugfix] | Balance history is now only sent to members of the account and to BankSystem admins; previously any player could request the history of any account |
| ![feature] | Admin commands and admin functions can now be granted per player with permission nodes (e.g. LuckPerms): `banksystem.admin.command.trust`, `.op`, `.backup`, `.symbols`, `.restorebinding`, `.exportrecipes`, `banksystem.admin.adminmode`, `banksystem.admin.software`. Without a permission mod, operator level 2 is required, as before |
| ![hardening] | Players can only load the data of bank accounts they are a member of; this now covers every way to read account data (balances, members, permissions and account details), and BankSystem admins can still see every account. Player lists in pickers now contain only player names |
| ![hardening] | Looking up another player's details, or whether they are a BankSystem admin, now only returns their name unless you are an admin |
| ![hardening] | The payout target picker no longer shows other players' account permissions |
| ![hardening] | Using the Banking Software on another player now also requires BankSystem admin rights |
| ![breaking] | Multi-server: on slave servers that are not trusted yet, display blocks show no data and BankSystem admin mode in `/banksystem manage` and `/bank manage` is not available until the slave is trusted with `/banksystem trust` |
| ![feature] | New permission node `banksystem.admin` (without a permission mod it falls back to operator level 2) and a new optional setting "Sync admin flag with LuckPerms" in Mod Settings → Integrations (off by default): with LuckPerms installed, `/banksystem op` and `/banksystem deop` also grant or remove the `banksystem.admin` permission, and granting or removing that permission in LuckPerms immediately makes the player a BankSystem admin or removes their admin rights. Existing BankSystem admins are copied to LuckPerms once when the setting is first turned on. Untrusted slave servers never change admin rights |
| ![feature] | Admin audit trail: every admin action (balance set/add/remove, unlocks, account edits, freezes, disallowed items, banks closed by an admin, balances destroyed because they could not be handed to a user an admin deleted) is written to a daily file in `<world>/data/BankSystem/audit/` on the master server and sent as a chat alert to online BankSystem admins, also on slave servers. `/banksystem alerts on\|off` lets each admin mute or unmute the chat alerts; the setting "Admin alerts on by default" decides for admins who never used it. The audit files are always written |
| ![feature] | Suspicious-activity flags: the master now flags banknote deposits of money the depositor did not withdraw themselves, very large withdrawals, sudden wealth jumps, large transfers, payouts or dividends into newly created accounts, a total money supply of all accounts that grows by more than 10% and more than $10,000,000 within an hour, a banknote withdrawal or a deleted user's payout on a slave server whose delivery could not be confirmed, and a currency-mod link that was suspended at start-up. Each flag is stored, written to the audit file and sent to admins as an alert; every check has its own on/off switch and thresholds (wealth jumps and money supply also a cooldown) in the new "Suspicious activity" settings, except the unconfirmed delivery and the suspended currency link, which are always on. Bank accounts now remember when they were created; accounts from older versions take the date of their first recorded activity |
| ![feature] | Daily audit digest: the master writes a short markdown summary of the previous day (money supply, top cash gainers, every flag, admin actions) to the audit folder, once per day. `/banksystem auditreport <hours>` writes one for the last 1 to 720 hours on demand and shows the file path |
| ![hardening] | Requests to the bank server, from a slave server or from the game, that get no answer in time or are cut off by a disconnect or a failed send no longer hang forever; they now fail. Bank transfers wait up to 30 seconds. Audit and history pages, the server network overview, company actions and admin commands wait up to 150 seconds, so a busy server or a running backup does not cut them off. Bank Download blocks keep working instead of getting stuck until their chunk reloads or the server restarts, Bank Upload blocks and terminal crafting give the item back instead of losing it, bank displays and their history try again, and Mod Settings shows the failure instead of loading forever. Admin commands report that the request to the master failed, and company screens and commands report that the bank server did not answer, instead of staying silent. When a dividend or catch-up payment gets no answer, the screen now says it may have gone through and keeps the Pay button off instead of reporting a failure |
| ![hardening] | Multi-server: deposits, withdrawals, converter deposits and banknote withdrawals between slave servers and the master are applied at most once, even if a request arrives twice. When such a transfer fails without a clear answer, the server that sent it asks the other server whether it went through and only gives the money or items back if it did not. A transfer whose outcome still cannot be confirmed is not refunded but logged, and an unconfirmed banknote withdrawal is flagged for admins. Bank terminal crafting and the Bank Download block keep items locked, instead of releasing them, when the master cannot confirm that it took them |
| ![bugfix] | Deleting a user who is online no longer pays out 100 times their balance: money is now handed out as banknotes of the right value and items in their real amount. Amounts smaller than one item are recorded as lost |
| ![bugfix] | Deleting a user no longer pays out money that is still in a linked external currency account; only what BankSystem itself holds for that slot is paid out |
| ![bugfix] | Players can only link a bank slot to their own external currency accounts (Numismatics, Lightman's Currency). Requests to link someone else's account, which could drain it, are refused |
| ![bugfix] | Live account updates in the bank terminal are only sent to account members and BankSystem admins |
| ![bugfix] | Display blocks can only be set to show accounts the player is a member of. BankSystem admins can still show any account |
| ![bugfix] | The server network overview (addresses, ports, online players) is only shown to BankSystem admins and the server console |
| ![hardening] | Players can no longer flood the item registry with endless custom item variants, and untrusted servers can no longer register new items |
| ![bugfix] | Other players can no longer look up your personal account number, whether you have one, an account's frozen state, or your full account list from the company payout picker |
| ![hardening] | Untrusted slave servers can no longer run bank commands, withdraw banknotes, or read player data on behalf of other players. `/money` and `/money circulation` still work there |
| ![bugfix] | Bank Download blocks only accept changes, including disconnecting, from players with withdraw permission on the connected account, and stop withdrawing once the player who connected them loses that permission. Download blocks placed before this update stay idle until a player with withdraw permission saves their settings once |
| ![bugfix] | Bank Terminal on a slave server: deposited items are now taken out of the terminal before the deposit is sent to the master, as the Bank Upload block already does. Before, a lost or late answer left the items in the terminal even when the master had already credited them, so they existed twice. Items come back only when the master confirms it did not take them; otherwise the transfer is logged for an admin |
| ![bugfix] | Linking a currency-mod account to a bank slot that is already linked is now refused (unlink it first). Before, re-linking copied the old account's balance into the new one without taking it from the old one, which duplicated money |
| ![hardening] | Linking a bank slot to another player's Numismatics or Lightman's Currency account could be abused before this release. On start-up the server now checks every existing link. A link that the account's owner or managers could not create themselves is suspended, also when the currency mod lists no accounts for them; if the currency mod cannot answer, the link is left alone. A suspended link moves no money: deposits, withdrawals and unlinking through it are blocked, and the bindings screen shows it as suspended. Admins get an alert for each suspended link and can restore a legitimate one with `/banksystem restorebinding`. Deleting the bank account, its player or the bank slot pays nothing out for a suspended link and leaves the external account untouched; the amount BankSystem held for it is logged and admins get an alert, so they can sort it out by hand. |
| ![hardening] | Stored items that start loading as the same item (for example after a mod update or removal changed their components) are no longer merged silently at startup. The server stops with a report listing every affected item, and the merge only goes ahead after you confirm it once with `CONFIRM_ITEMID_MERGE`. Small automatic clean-ups of duplicates created during the current session still happen and are now logged. |
