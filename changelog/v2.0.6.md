# 2.0.6 — In Development

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | Added an "Allow all items" server setting — when on, the mod's blacklist becomes the sole gate on what can be banked, so admins running large modpacks no longer need to curate an item-by-item allow-list. Off by default; existing worlds keep today's whitelist behavior. |
| ![bugfix] | <details><summary>Currency Bindings screen: provider picker now opens the account picker instead of jumping back to the bindings list on 2+ provider setups</summary><br>With more than one currency mod loaded (e.g. Numismatics **and** Lightman's Currency), clicking a provider tile bounced straight back to the bindings list instead of showing that provider's available accounts. Root cause: the provider button's falling-edge callback both set the next screen and then immediately closed itself back to the parent, clobbering the navigation — the same defect class already fixed in the sibling account picker. Removed the stray close call so the account picker stays on screen.</details> |
| ![feature] | The Bank Upload and Bank Download screens now hide JEI's item overlay while they're open, so nothing gets in the way of the container inventory view. JEI is restored when you close the screen. Third-party JEI addon buttons may still appear — those are not under this mod's control. |
| ![bugfix] | <details><summary>Bank Terminal balance now updates live while the screen is open</summary><br>Since v2.0.5 the terminal appeared frozen after any balance-affecting event — deposits from another screen, another player's transaction on a shared account, StockMarket order fills, and external currency mod writes (Numismatics, Lightman's) all failed to refresh the open view. The v2.0.5 currency-bindings work introduced bound-slot code paths in every balance-mutation method that forgot to signal the account-change stream; the stream stayed silent and the terminal never learned about the change. Every bound-slot mutation now signals correctly, and a 1 Hz drift watchdog catches balance changes made through an external currency mod's own UI so those propagate too. Regression tests added.</details> |

## Integrations

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Bank Upload and Bank Download blocks now connect to modded item-transport systems (PrettyPipes and friends)</summary><br>Vanilla hoppers already worked with the upload/download blocks because they use Minecraft's `Container` interface directly, but modded pipe systems (PrettyPipes on NeoForge, and any Fabric Transfer API consumer such as Modern Industrialization or AE2-Fabric) look for a platform-specific item-handler view and skipped the blocks as "not an inventory." The block entities now expose an `IItemHandler` capability on NeoForge (via `InvWrapper` against `RegisterCapabilitiesEvent`) and an `ItemStorage.SIDED` view on Fabric (via `InventoryStorage.of`). NeoForge tested in-game with PrettyPipes. Fabric registration ships alongside but was not manually tested this session.</details> |

## Documentation

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>New user guide walks players through binding a bank slot to a Numismatics or Lightman's Currency account</summary><br>`documentation/user-guide/CurrencyBindings.md` covers the full bindings-screen workflow with screenshots: personal vs shared account matching, coin-variant deposits at bank terminals, the three-way unbind choice (keep on BankSystem / keep on provider / cancel), drift behavior when the external balance changes outside BankSystem, per-provider notes for Numismatics and Lightman's Currency, and troubleshooting for item-mismatch and provider-unavailable states. ## Internal

| Tag | Change |
|---:|---|
| ![improvement] | The JEI overlay hide/show logic now lives in ModUtilities' shared GUI API, so other mods using ModUtilities can opt in with a single method call. No player-visible behavior change on BankSystem's screens. |
| ![improvement] | <details><summary>Added regression tests locking in the money-denomination resolver (Issue #57 verification)</summary><br>Two new in-game tests in the ItemID identity suite scan every registered money denomination through the resolver and assert no two stored templates share a normalized identity. Both pass on the current build, confirming the resolver behaves deterministically in practice — the defensive layers added in prior versions (volatile-component copy discipline, post-load money-short refresh, denomination-agnostic cash detection) close the original non-determinism report even though the underlying first-match lookup on a ConcurrentHashMap is architecturally unchanged. If a future regression reintroduces duplicate templates, the invariant test flags it immediately.</details> |
