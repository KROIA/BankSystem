## Security

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>Running the in-game test suite could delete real item entries from the world's item registry</summary><br>The cleanup that rolls back the test suite's temporary items decided what to remove using the item handed to it rather than the registry row it actually matched, so re-using an everyday item in a test (money, paper, iron ingot) could wipe that item's real registry entry when the suite finished. The rollback now proves a row belongs to the test suite before removing it, and only removes entries the suite itself created.</details> |
| ![hardening] | <details><summary>The item allow-list now self-heals entries left behind by an older test run</summary><br>Servers that ran the in-game test suite on an affected version may be carrying allow-list or blacklist entries pointing at items that no longer exist, which showed up as blank "air" rows. These unresolvable entries are now dropped automatically, so an affected world repairs itself the next time the suite runs.</details> |

## API

| Tag | Change |
|---:|---|
| ![feature] | Added `ServerBankManager.snapshotItemFilters()` / `restoreItemFilters(...)` and the accompanying `ItemFilterSnapshot` record, which capture and restore the allowed-item set and the runtime blacklist verbatim. Unlike disallowing an item, restoring a snapshot performs no account clearing and no company-currency cascade, so it can express the "neither allowed nor blacklisted" state that the allow/disallow pair cannot. |

## Internal

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>New shared guard that snapshots and restores the live world state touched by the in-game test suite</summary><br>A single helper now captures the item allow-list, the runtime blacklist, the trusted-slave server set and the complete item registry (including its alias map, quarantined aliases and short counter) before a test section runs, and hands the server back exactly what it found afterwards. It is null-safe throughout and never throws out of the cleanup path.</details> |
| ![bugfix] | Running `/banksystem test` no longer leaves artefacts behind in the live world — the currency-adapter sections leaked a test user, a bank account and permanently allowed items on every run, and the multi-server security section could strand an administrator test user. Those users, accounts, items and trusted-slave entries are now all removed again. |
| ![bugfix] | The multi-server security section no longer "reverts" its temporary items by blacklisting them. Blacklisting an item clears it from every account without refund, which left a worse artefact than it cleaned up; the section now restores the original filter state instead. |
| ![improvement] | Test-suite cleanup now runs even when a test fails. Nine sections moved their state restore into a guaranteed cleanup block, early returns no longer skip it, and the restore runs last so teardown work is no longer performed against already-rolled-back state. |
